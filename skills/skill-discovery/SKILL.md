# Skill Discovery — 能力沉淀器

## 触发约束

此 skill **仅通过显式调用触发**。

### ⛔ 不触发的场景
- 用户提到"发现模式"、"提炼能力"等但未提及 skill-discovery
- 完成任务后的"顺便"扫描
- 用户未显式引用 @skill-discovery

### ✅ 触发条件
必须同时满足：
1. 用户明确说出"使用 skill-discovery"或"启动 skill-discovery"，或显式引用 @skill-discovery
2. 用户提供了明确需求或上下文

---

## 问题

在使用 agent 的过程中，我们积累了大量隐性知识和工作模式：

1. **反复纠正同一个行为**——每次都教，但从不沉淀
2. **同类修复反复出现**——同样的 bug 修了又修
3. **工作模式被遗忘**——某个流程跑通了，下次又从头摸索
4. **Anti-pattern 反复踩**——文档里写了但 agent 不看

**如果不主动提炼，这些能力就会流失。** 这个 skill 就是让"从经验中提炼能力"这件事本身变得可重复、系统化。

---

## 核心原则

```
扫描 → 聚类 → 评估 → 草案 → 用户确认
```

每个阶段都是必需的：
- **扫描**不是罗列，而是识别模式
- **聚类**不是去重，而是发现共性
- **评估**不是打分，而是判断杠杆
- **草案**不是笔记，而是可用的 SKILL.md
- **确认**由用户审查决定，skill 不自动写入任何文件

---

## 执行流程

### Phase 1: 多源扫描

按以下顺序扫描项目，收集原始信号：

#### 1a. Git 提交模式

```bash
# 提交类型分布
git log --oneline -100

# 修复模式聚类
git log --all --oneline --grep="fix" --grep="修复" --grep="bug" -i -50

# 重构模式
git log --all --oneline --grep="refactor" --grep="重构" -i -50

# 同类问题反复修？
git log --all --oneline --grep="yaml" --grep="schema" --grep="格式" -i -30
```

提取信号：
- **同类修复反复出现** → 预防性 skill 候选
- **同一模块频繁重构** → 架构约束 skill 候选
- **跨文件同步修改** → 一致性 skill 候选

#### 1b. Agent 对话模式

扫描 `~/.cursor/projects/*/agent-transcripts/*.jsonl`（或项目本地 transcripts 目录）：

提取信号：
- **用户反复下达的同类指令** → 自动化 skill 候选
- **用户反复纠正的 agent 行为** → 护栏 skill 候选
- **agent 反复犯的同类错误** → 约束 skill 候选
- **"你应该先读..."类提醒反复出现** → 流程 skill 候选

#### 1c. Feature/Issue 模式

读取项目中的 feature.md、TODO、issue tracker 等：

提取信号：
- **已完成功能中反复出现的模式** → 专项 skill 候选
- **用户反复提到的痛点** → 体验 skill 候选
- **"总觉得有问题"的功能** → 优化 skill 候选

#### 1d. 现有 Skill 覆盖度

扫描 `.claude/skills/`、`~/.cursor/skills/`、`~/.codex/skills/` 等：

提取信号：
- **哪些 skill 被高频调用** → 考虑拆分为子流水线
- **哪些 skill 从未被引用** → 可能已过时
- **哪些 skill 总是组合使用** → 考虑合并或新建流水线

#### 1e. 约束与规则模式

扫描 `AGENTS.md`、`.cursor/rules/`、`.codex/rules/` 等：

提取信号：
- **"MUST" / "NEVER" / "禁止" 反复出现的领域** → 可能值得独立 skill
- **规则写得很长但仍被违反** → 可能需要脚本门控而非纯文案

---

### Phase 2: 模式聚类

将 Phase 1 收集的信号按语义分组：

| 聚类方法 | 说明 |
|---------|------|
| **按触发条件** | "当 X 发生时，总是做 Y" |
| **按影响范围** | 全局 / 项目级 / 模块级 |
| **按出现频率** | ≥2 次才考虑，≥5 次优先 |
| **按修复代价** | 每次修复耗时 × 出现次数 = 累计代价 |

聚类后过滤掉：
- 单次事件（不具复用性）
- 过于特定（只在某一次 commit 中出现）
- 成本过高（需要人工判断且无法标准化）

---

### Phase 3: 价值评估

每个候选模式按以下标准评估：

| 指标 | 权重 | 评分标准 |
|------|------|---------|
| **频率** | 30% | 1分=2次, 2分=3-4次, 3分=5-9次, 4分=10+次 |
| **代价** | 25% | 1分=<5分钟, 2分=5-15分钟, 3分=15-60分钟, 4分=>1小时 |
| **杠杆** | 25% | 1分=预防1次, 2分=预防2-3次, 3分=预防4-10次, 4分=预防10+次 |
| **通用性** | 20% | 1分=仅本项目, 2分=同类项目, 3分=多数项目, 4分=所有项目 |

**综合评分 = 频率×0.3 + 代价×0.25 + 杠杆×0.25 + 通用性×0.2**

优先级划分：

| 优先级 | 评分 | 行动 |
|--------|------|------|
| **P0** | ≥ 3.0 | 立即提炼，生成完整 SKILL.md 草案 |
| **P1** | 2.0 - 2.9 | 建议提炼，生成草案框架 |
| **P2** | 1.0 - 1.9 | 记录在案，适时提炼 |
| **IGNORE** | < 1.0 | 一次性事件，不提炼 |

---

### Phase 4: Skill 草案生成

为 P0 和 P1 候选生成 SKILL.md 草案，遵循以下格式：

```yaml
---
name: {skill-name}
description: {1句话描述，说明用途和触发条件}
when_to_use: {具体的触发条件，用户说什么时会触发}
---

# {Skill 标题}

## 问题
{这个 skill 解决什么问题，用真实案例说明}

## 核心原则
{1-3 条核心原则，不超过 10 行}

## 执行流程
{步骤化的操作指南，每步包含具体命令或操作}

## 约束与原则
{MUST / NEVER 规则}

## 示例
{1-2 个真实示例}
```

**草案质量要求**：
- MUST 包含真实案例（从扫描数据中提取）
- MUST 遵循已有全局 skill 的格式规范
- MUST 包含明确的触发条件
- MUST 包含可执行的步骤，不只是描述
- NEVER 编造未扫描到的模式
- NEVER 生成空模板或占位符

---

### Phase 5: 用户审查与输出

生成 **能力发现报告**（见下方格式），展示给用户审查。

**审查流程**：
1. 展示报告摘要（候选清单 + 评分）
2. 逐个展示 P0/P1 草案
3. **等待用户反馈**：
   - 哪些候选用户认可
   - 哪些需要调整
   - 用户希望把草案写到哪个路径
4. **本 skill 不执行任何文件写入操作**
   - 报告和草案均以对话文本形式输出
   - 如果用户明确指示"写到 XXX 路径"，才执行写入
   - 绝不自作主张决定输出位置
5. **不自动执行 git commit**

---

## 硬约束

- **MUST 只读扫描** — 扫描阶段不修改任何项目数据
- **MUST 输出文本** — 报告和草案以对话文本形式输出，不默认写文件
- **MUST 用户指定写入路径** — 只有用户明确说"写到 XXX"时才写入
- **MUST 遵循格式** — 草案与用户已有全局 skill 格式一致
- **NEVER 自动写入文件** — 不写入 skill 目录、不写入临时文件、不写入任何位置
- **NEVER 编造模式** — 不凭空想象可能的 skill
- **NEVER 自动注册** — skill 的创建、注册、提交全部由用户手动完成
- **NEVER 扫描敏感数据** — 跳过 credentials、tokens、.env 等文件
- **NEVER 在扫描失败时静默跳过** — 明确报告哪些数据源不可用

## 扫描目标参考

默认扫描以下位置的全局 skill：
- `~/.cursor/skills/`
- `~/.codex/skills/`
- 用户指定的 skill 仓库路径

### 项目 Skill

默认扫描当前项目的：
- `.claude/skills/`
- `.cursor/rules/`
- `AGENTS.md`

### Agent Transcripts

默认扫描：
- `~/.cursor/projects/*/agent-transcripts/*.jsonl`
- `~/.codex/projects/*/agent-transcripts/*.jsonl`
- 项目本地的 transcripts 目录（如有）
