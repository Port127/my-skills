# 社区调研策略

> 项目分析时"去哪里找、搜什么、提取什么"的通用策略。
> 具体的搜索结果因项目而异，需要运行时搜索。

---

## 1. 调研内容矩阵

| 维度 | 要提取的信息 |
|------|-------------|
| **GitHub 数据** | Stars/Forks/Watchers/Contributors/Issues/Releases、Trending 历史 |
| **作者/团队** | 背景、动机、其他项目、活跃度 |
| **社区覆盖** | 哪些平台有讨论、内容类型 (教程/评测/讨论)、语言分布 |
| **用户反馈** | 正面评价、负面评价、常见抱怨、功能请求 |
| **竞品对比** | 同类项目列表、差异化特性、市场定位 |
| **衍生生态** | Fork、衍生项目、集成案例 |
| **知名收录** | 是否被 GitHub Blog、InfoQ、知乎周刊等推荐 |

---

## 2. 平台覆盖策略

|------|----------|----------|

| 来源 | 获取方式 |
|------|----------|

| NPM/PyPI/Crates.io | 包管理平台查询下载量 |

## 3. 搜索词策略

### 基础搜索

```
"{项目名}"                          — 精确匹配
"{项目名}" {作者名}                  — 带作者
"{项目名}" review OR 评测 OR 使用    — 评价类
"{项目名}" tutorial OR 教程          — 教程类
"{项目名}" alternative OR 替代品     — 竞品讨论
```

### 社区定向搜索

```
site:zhihu.com "{项目名}"
site:reddit.com "{项目名}"
site:v2ex.com "{项目名}"
site:csdn.net "{项目名}"
```

### 竞品搜索

```
"{项目名}" vs {竞品名}
"{项目类别}" open source alternatives
"{项目类别}" 开源 推荐
```

---

## 4. 竞品对比框架

搜集竞品信息时，关注以下维度：

| 维度 | 对比内容 |
|------|----------|
| 规模 | Stars/用户量/下载量 |
| 技术栈 | 语言、框架、架构 |
| 功能 | 核心功能覆盖度 |
| 活跃度 | 最近提交、Issue 响应 |
| 差异化 | 独特卖点 |
| 定价 | 免费/开源/商业 |

---

## 5. 用户反馈分类

收集到的用户反馈分为：

```
正面反馈 (Positive)
├─ 功能赞颂
├─ 使用体验好评
└─ 推荐语

负面反馈 (Negative)
├─ Bug 报告
├─ 功能缺失
├─ 体验问题
└─ 性能抱怨

建议 (Suggestions)
├─ 功能请求
├─ 改进建议
└─ 集成需求
```

---

## 6. 调研结果组织

最终将调研结果组织为：

1. **GitHub 数据表格** — 核心指标一览
2. **社区覆盖地图** — 各平台覆盖度 + 内容类型
3. **用户反馈摘要** — 正面/负面/建议分类
4. **竞品对比表** — 多维度对比
5. **关键发现** — 3-5 条最重要的洞察
