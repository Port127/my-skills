# Design System Notes

## Layout

- Keep the primary task visible without making secondary controls compete with it.
- Group related fields and actions; use spacing before adding another border or card.
- Preserve a readable content width for long descriptions and code samples.
- On narrow screens, keep essential names, status, and row actions reachable.

## Components

- Use buttons for actions and links for navigation.
- Keep destructive actions visually distinct and adjacent to their confirmation step.
- Present loading, empty, error, and success states with specific next actions.
- Reuse the existing component pattern before introducing a new visual treatment.

## Copy

- Lead with the user's task or the current state.
- Prefer concrete labels such as `Retry scan` over vague labels such as `Try again`.
- Explain an unavailable action next to the control that caused it.
- Keep security results advisory and describe what the user can inspect next.
