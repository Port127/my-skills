# Git Commit Message Generator

## 触发约束

此 skill **仅通过显式调用触发**。

### ⛔ 不触发的场景
- 用户完成代码变更但未提及 commit-msg
- 用户提到"提交"、"commit"等通用请求但未提及 commit-msg
- 用户未显式引用 @commit-msg

### ✅ 触发条件
必须同时满足：
1. 用户明确说出"使用 commit-msg"或"启动 commit-msg"，或显式引用 @commit-msg
2. 用户提供了明确需求或上下文

---

## 执行流程

### Phase 1: 收集变更信息

执行以下命令获取变更状态：

```bash
git status
git diff --cached
git diff
```

分析变更内容，理解：
- 修改了哪些文件
- 变更的性质（新增、修改、删除、重构）
- 变更的业务/技术含义

### Phase 2: 生成 Commit Message

遵循 Conventional Commits 规范生成提交信息：

```
<type>(<scope>): <subject>

<body>

<footer>
```

**Type 类型**：
- `feat`: 新功能
- `fix`: 修复 bug
- `docs`: 文档变更
- `style`: 代码格式（不影响代码运行）
- `refactor`: 重构
- `perf`: 性能优化
- `test`: 测试相关
- `chore`: 构建/辅助工具变动
- `ci`: CI 配置变更

**Scope**（可选）：变更影响的模块或范围

**Subject**：简短描述（不超过 50 字符，首字母小写，结尾不加句号）

**Body**（可选）：详细说明变更原因和影响

**Footer**（可选）：不兼容变更说明或关闭的 Issue

### Phase 3: 清理供应商文案

**严格过滤以下内容**：
- `Made-with: Cursor`
- `Made-with: claude`
- `Made-with: openclaw`
- `Made-with: codex`
- 任何包含 `Made-with`、`Generated by`、`Created with AI` 等 AI 供应商标识的文案
- 类似的供应商标记或水印

**过滤规则**：
- 从 commit message 中完全移除这些内容
- 不要解释为什么移除，直接清理
- 确保最终输出不包含任何 AI 工具供应商信息

### Phase 4: 输出并等待确认

输出格式：

```markdown
## 建议的 Commit Message

```
<生成的完整 commit message>
```

## 变更摘要
- 文件 1: 简要说明
- 文件 2: 简要说明

---
请检查以上提交信息，确认后执行：
```bash
git commit -m "<subject>" -m "<body>"
```
或告诉我需要调整的地方。
```

---

## 约束与原则

- **绝不自动提交**：只生成 commit message，由用户手动执行
- **必须过滤供应商文案**：这是硬性要求，不得以任何形式保留
- **遵循 Conventional Commits**：确保提交历史规范统一
- **简洁优先**：subject 行尽量简洁，细节放在 body 中
- **中文友好**：如果项目主要使用中文，允许中文 commit message
- **多文件合并**：如果多个相关文件属于同一逻辑变更，合并为一个 commit

## 示例

### 示例 1：功能开发

```
feat(create-skill): 添加质量校验阶段

Phase 5 新增 quality validation，检查 skill 是否符合规范
包括触发规则、结构完整性、命名公约等校验项

关联: #42
```

### 示例 2：Bug 修复

```
fix(task-executor): 修复任务状态不同步问题

当 round 完成后，BUG_TASKS.md 未正确更新状态
现在确保文档与实际任务状态保持一致
```

### 示例 3：重构

```
refactor: 统一 skill 配置结构

将所有 skill 的 config.json 改为统一的 schema
移除冗余字段，增加版本控制
```
